## Contribution

### Lint / format rules
- Rust: `cargo clippy --all-targets --all-features -- -D warnings` is a hard gate — zero lints tolerated. `cargo fmt --check` enforces formatting. Strong, enforced baseline.
- JS/TS: `oxlint` with strict rules (eqeqeq always, no-implicit-coercion, ban-types, explicit return types, no-unsafe-* as errors). `oxfmt` enforces single quotes + 120 print width. Enforced in CI before merge.

### SAST / DAST
- No dedicated SAST/DAST tool (e.g. CodeQL, Semgrep) is wired into the pipelines today.
- `cargo-audit` (Rust advisory DB) runs in Phase 1 but is **advisory only** — findings do not block the PR.

### Secret & dependency scanning
- Secrets are injected via GitHub Actions `secrets` and a `BOOTSTRAP_KEY` env var; `.env` is git-ignored and generated by `scripts/ci/setup-env.ts`. No secret-scanning tool (e.g. gitleaks) is configured.
- Dependency scanning is limited to `cargo-audit`; no SCA for the JS/TS `devDependencies` (oxlint/oxfmt) beyond npm's own advisories.

### Supply-chain controls
- `Cargo.lock` is committed and builds use `--locked`, giving reproducible Rust builds. Good supply-chain hygiene.
- Docker base images are pinned (e.g. `rust:1.88-alpine3.21`, `postgres:17.2-alpine3.21`, `caddy:2.8.4-alpine`). Image tags are version-pinned, not `latest`.

### Gaps the interview must resolve
- Should `cargo-audit` (and ideally a JS/TS SCA) be promoted to a blocking gate?
- Is a secret-scanning step (gitleaks) wanted pre-merge?
- Is a formal SAST (CodeQL/Semgrep) in scope, or out of scope for this team's maturity?

## Positions
- AGREE: pinned base images + locked Cargo builds are good supply-chain practice; affirm them.
- OBJECT: cargo-audit being non-blocking and the absence of any secret-scanning/SAST is a security gap that needs an explicit human decision, not a silent default.
